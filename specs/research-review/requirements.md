# 研究综述路径：需求与范围

日期：2026-09-07；状态：开发方案，尚未实现。主仓库为 writing-agent-v2-oss；商业版在每个里程碑同步公共变更并独立验证。本目录不代表部署或测试通过证明。

## 1. 产品决策

增加一个用户可选的「研究综述」写作路径，使用现有文档、合同、运行、素材、编辑器、质量报告和版本管理。先实现“学术检索 → 可追溯阅读 → 冻结证据 → 用户确认 → 提纲 → 用户确认 → 现有 Writer → 引用校验 → 正式版本”。AR-012 作为后续候选生成器对照实验。

不把 AutoResearch 工作台、LangGraph 编排和 SQLite 项目状态搬进产品。首版提供叙述性研究综述，不宣称系统综述、穷尽检索或科学真实性认证。现有快写、提纲写作、素材写作继续沿原模板运行。

工程上新增 `research_review` orchestration mode 与 `tpl_research_review_v1`。原因：当前 TemplateRegistry 每种 mode 只允许一个模板；直接替换 strict_research 会改变已有合同的执行路径。研究综述必须由用户显式选择，auto 首版不自动推荐；strict_research 保持原语义。

## 2. 用户旅程

1. 在现有写作入口选择研究综述，填写研究问题、目标读者、语言/长度、可选年份范围和主题排除条件，选择是否联网，附入自己的论文材料。
2. 看到检索、筛选、全文获取、阅读进度。来源卡区分“仅元数据”“已读摘要”“已读全文”，展示选中/待补充/未评分原因。
3. 阅读结束形成不可变候选证据包；界面显示可用文献数、全文数、关键主题覆盖、矛盾结论与缺口。用户确认该版本，或调整材料/要求后启动新运行。
4. 系统生成带来源绑定的综合提纲。用户确认具体版本，或修改提纲后确认新版本。确认前不调用正文 Writer。
5. 编辑器接收草稿；引用点开可看原文摘录、页码/块位置和文献。质量报告明确引用完整性、证据范围与待人工核查项。
6. 达到交付条件后提交正式文档版本；运行失败保留已完成产物与可恢复进度。

首版不做运行中反复选删论文、局部重算整个 DAG；证据确认页的“修改材料”创建新合同版本/新运行，按输入哈希复用安全缓存。提纲编辑只在尚未完成的提纲确认点生成新的不可变提纲 Artifact，不修改旧产物。

## 3. 可验收需求（EARS）

| ID | 条件与系统行为 | 验收依据 |
|---|---|---|
| R01 | 当用户未选择研究综述时，系统应保持原模板、合同哈希与写作行为 | 旧模式/历史合同回归 |
| R02 | 当合同禁止外部研究时，系统应只读取用户授权材料，不调用检索/OA/下载接口 | 网络 mock 调用计数为 0 |
| R03 | 当检索得到同一论文的 DOI URL、裸 DOI 或元数据别名时，系统应合并可确定的重复记录，保留来源追踪 | 去重固定样本；歧义不强并 |
| R04 | 当相关性模型失败时，系统应保留未评分记录和降级理由，不把失败当不相关，不生成虚构论文 | 超时/429 样本 |
| R05 | 当只有摘要或全文无法解析时，系统应标记 abstract 或 unread，不生成全文级证据 | 摘要/扫描 PDF 样本 |
| R06 | 当 Reader 输出 claim 时，每条 source_assertion 应有可验证 quote、document hash、block hash 和区间；推断/假设单独标记 | 证据校验与篡改样本 |
| R07 | 当材料包或提纲尚未被确认时，系统应暂停在对应 gate，刷新/重启/普通 resume 不得绕过 | API + 重启测试 |
| R08 | 当用户确认 gate 时，系统应校验其所有权、plan hash 与产物哈希，并恰好完成该 gate 一次 | 并发确认/过期确认测试 |
| R09 | 当原始文件、研究问题或 Reader 版本改变时，系统应使相应缓存失效，既有冻结包继续可回溯 | 输入哈希矩阵 |
| R10 | 当 Writer 生成事实性表述时，系统应保留 claim/evidence 引用链；不能把检索分数或模型判断当事实保证 | 输出引用与人工抽检 |
| R11 | 当正文存在不存在的引用或失效证据时，系统应阻止正式提交；普通缺口应进入需人工复核状态 | 质量门负例 |
| R12 | 当进程重启、远端超时或取消发生时，系统应保留持久状态，使 GET 与事件最终一致，且不自动重复未知结果的付费调用 | 故障注入 |
| R13 | 当 AR-012 候选生成时，系统应使用同一冻结证据包，记录版本/用量，且不覆盖正式版本 | shadow 隔离测试 |
| R14 | 当研究服务未启用或不可用时，系统应明确显示不可用，不静默降级到普通快写 | feature flag / 断连测试 |

## 4. 首版默认边界（拟定值，必须写入 ResearchSpec 后再哈希）

- 最多 3 条 query、60 条合并后候选、20 篇阅读；单论文最多 24 个有界文本块。首版论文处理并发 1，稳定后允许 2。
- 下载单文件上限 25 MiB，仅支持文本型 PDF、TXT、Markdown；扫描件显示需补充可读文本。不得把“PDF 可打开”显示成“全文已读”。
- 默认至少 5 篇可引用来源才允许证据确认；选“必须全文”时每篇参与证据的来源都必须 full_text。少于 5 篇时调整合同重跑，首版不提供无审计的强制跳过按钮。
- 来源数阈值是产品的充分性底线，不是学术质量保证。主题覆盖/冲突需要人工确认，不依赖单一总分。
- 节点与调用耗时独立计量；默认运行主动执行时间上限 30 分钟，人工等待不计入主动执行预算；成本上限显式确认，不能把未知费用记成零。
- 不做 OCR、付费墙绕过、复杂表格/公式语义解析、自动投稿、全自动长篇反复改稿、生产自动模型路由。

## 5. 完成定义

完成首版 = R01–R12/R14 的自动化验收通过 + 真实 HTTP 全流程至少一次完成（含两个 gate、断线重连）+ 三类主题各两次人工检查 + OSS/商业版构建回归通过。通过离线测试、单个模型调用成功或页面看起来完整，都不能单独标记上线完成。

AR-012 是否成为正式生成选项是独立里程碑，不属于首版完成前提。上游标注 Proprietary；复制/分发代码前必须明确许可。若无许可，采用本方案的接口与行为重新实现，并记录代码来源，不把上游源码直接放入 OSS 镜像。
