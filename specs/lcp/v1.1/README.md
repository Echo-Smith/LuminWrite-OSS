# LCP v1.1 Protocol Schema (research review)

v1.1 extends the v1 WritingContract with exactly one change: the top-level
`research` object (`ResearchSpec`, contracts.md §1 of
`specs/research-review/contracts.md`). Everything else — controls,
provenance, inference state, hash format — is unchanged from
[`../v1`](../v1/README.md).

- `schema_version` is `lcp/1.1`. A v1.0 contract must not carry `research`;
  a v1.1 contract must carry it and pass `ResearchSpec.Validate`.
- Only `orchestration_mode: research_review` is new; the compiler fails
  closed unless the contract is `lcp/1.1` with a non-empty research spec
  (`backend/internal/writingplan/compiler.go`).
- Cross-field numeric constraints (`year_from <= year_to`,
  `min_citable_sources <= max_papers <= 20`, `max_candidates >= max_papers`,
  `max_candidates <= 60`, `max_queries` 1..3) are semantic, enforced by the
  Go validator (`backend/internal/writingkernel/research_spec.go`), not by
  structural JSON Schema.
- Unknown fields are rejected at both the contract and the research-object
  level (`DecodeWritingContractResearchStrict`).
- v1.0 contracts are byte-stable: the `research` field is trailing and
  `omitempty`, guarded by golden hash tests in
  `contract_golden_test.go`.

`fixtures/writing-contract.research-review.valid.json` is generated by the
Go tests and round-trips through strict decode + `Validate`.
