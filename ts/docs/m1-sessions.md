# 会话与派生文档

日期：2026-10-16。这一层叠在 M0 上。正文的真相仍然只在 Postgres 的版本链里。

## 会话

一篇文档有一个默认主会话，也可以再开会话。种类是 `main`、`fork`、`api`、`collab`。外部 Agent 用 `api`，其他人类用 `collab`。他们和主会话共享的只有这篇文档和它的版本链。

会话行只记 `document_id`、`kind`、`base_version_id`、`pi_conversation_id`、创建者和状态。没有正文栏。Pi 对话按会话创建，不按文档复用。回合开始时读取文档档案（大纲、关键决定、引用、要求），不回放别的会话的聊天。

分叉会话从某一版正文开始，记下那一版的 `base_version_id`。它提交的仍是普通 EditOp。服务端拿当前版本做锚点校验：对不上就拒绝（`hash_mismatch`），不会静默覆盖，也不会自动收成提案。锚点还能对上的块可以单独落下。所以旧分叉改已经变过的第 3 段会被拒绝，没变过的第 5 段可以应用。

一篇会话可以读取多篇文档（`session_reads`）。一批 EditOp 只能指向一篇文档，而且只能是这个会话所属的那一篇。要改另一篇，就为那一篇另开会话。

子 Agent 仍然是这个会话的 Pi 对话下面的 task 子对话，不挂在文档上。M1 的这一步还没有真正拉起子 Agent。

pi-durable 的 `conversation.fork(at)` 复制的是聊天记录，对不上「从某一版正文分叉、并且不回放聊天」。所以文档分叉用新的 Pi 对话，第一回合的上下文是档案加上那一版的块列表。

## 派生文档

派生文档不是分叉会话。`deriveDocument(versionId, { inheritDossier })` 把文档 A 的某一版正文复制成一篇新的文档 B。B 有自己的主会话、版本链和档案。改 B 不会改 A，A 可以列出自己的派生文档。

聊天记录不复制。派生完成时 B 的主会话还没有 `pi_conversation_id`。

`inheritDossier` 为真时复制大纲、引用和要求。关键决定不复制，B 的档案版本从 1 重新计。为假时档案是空的。

块 id 用新的 `blk_` id，不做命名空间。哈希不含块 id，所以相同文本的哈希还一样；锚点带块 id，所以 A 的修订不能命中 B，反过来也一样，结果是 `block_not_found`。把 B 的段落写回 A，是 A 的会话读 B、再对 A 的当前块提交 EditOp。过期锚点照旧拒绝。

## 测试

数据库测试覆盖档案的版本冲突、分叉的基准版本、派生后的块 id、档案继承、B 的修改不影响 A、跨文档一批修订被拒绝、用对方块 id 写回来被拒绝、用自己的锚点写回成功。Harness 测试覆盖主会话改第 3 段、分叉的过期第 3 段被拒绝、第 5 段落下，以及两个 Pi 对话 id 不同。`pnpm demo` 把这条路径走完，并加上派生和写回。都不需要模型密钥。
