双引擎设计

两套编排引擎按场景切换
⚙️ Pipeline (AgentEngine)
状态机管道模式：16 个 Step 顺序执行，每步可暂停/恢复，6 层退出保护。适合确定性流程。
  • 步骤固定：记忆→意图→检索→过滤→压缩→提纲→写作→自检→修正
  • 每步独立超时 + 优雅降级
  • 关键步骤失败终止，非关键步骤失败跳过
  • Token 预算 30 万 + 断路器（3 次连续失败）
🧠 Harness (LLM Agent Loop)
单层 LLM 编排模式：LLM 自主决定调用工具，最多 12 轮迭代。会话状态跨轮保留。
  • 工具粒度细：search_web / search_knowledge / read_source / write_article / review_article
  • 意图判定走规则（毫秒级），不走 LLM
  • LLM 自主决定何时搜索、何时写作、何时修正
  • 不存在外层 ReAct + 内层 agent loop 嵌套

6 层退出保护机制

Agent Engine 在每个 Step 执行前按优先级依次检查 6 层退出条件
L1 用户取消
cancelCh 信号 → 发送 agent.cancelled，终止流程
L2 全局超时
context.WithTimeout (5min) → error{code:"timeout"}
L3 Token 预算
CheckBudget (300K tokens) → error{code:"budget_exceeded"}
L4 WS 断连
disconnectCh → paused{reason:"disconnect"}，暂停非终止
L5 断路器
ConsecutiveLLMFails ≥ 3 → error{code:"circuit_breaker"}
L6 单步超时
Step.Timeout() → Critical 决定降级或终止

优雅降级策略

步骤关键超时降级行为
IntentStep关键30s失败 → 终止流程
SearchStep非关键45s失败 → 跳过，用已有素材继续
RelevanceStep非关键30s失败 → 跳过，不过滤
WriteStep关键180s失败 → 终止流程
PostReviewStep非关键60s失败 → 跳过，不评分
AutoFixStep非关键90s失败 → 跳过，不修正
